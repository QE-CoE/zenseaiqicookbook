# May 2026

## Highlights

### Fixed — Pending Review race condition

Validated agent outputs were occasionally flipping back to "Pending Review" after navigation. Root cause: the backend `PATCH /agent-outputs/:id/validate` is fired asynchronously while the user typically navigates immediately, so a subsequent `hydrateProjectFromBackendAsync()` would overwrite the local `validated: true` with the still-stale backend `validated: false`.

**Fix:** the hydration reconciler now preserves `validated: true` for any backend output whose `runId` matches a locally-validated row, both at the project-key cache and the per-pipeline mirror.

### Improved — Auto-PlayPilot label cleanup

The mode previously called **"Test Script Generation (Existing Framework)"** is now simply **"Test Script Generation"**. The mode covers both:

- Generating into a freshly scaffolded framework
- Generating into an **existing** project (zip upload or Git URL)

The mode-landing description was updated to reflect the broader scope.

### Fixed — One run-report per generation

Auto-PlayPilot's `save-config` step was incorrectly persisting an `AgentOutput` row under the same `agentCode` as `generateProject`, producing **two run reports** per single user-initiated generation (one empty from save-config, one real from generate).

**Fix:** `saveConfig` no longer passes `runId` to the multipart execute endpoint, routing it through the one-off endpoint instead. Generate is now the sole producer of an `AgentOutput` row for a given run.

### Reaffirmed — Backend canonical

After the May reconciliation, `pipeline_runs` and `agent_outputs` are unambiguously the source of truth. The frontend localStorage cache is a hot read-layer that:

- Survives backend outages (graceful degradation)
- Holds optimistic writes (validate, edit refined stories) for instant feedback
- Reconciles via `hydrateProjectFromBackendAsync()` on every project/pipeline mount

## Other changes
