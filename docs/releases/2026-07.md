# July 2026

## Highlights

### New — DeepSpeci v2

[DeepSpeci](../agents/deepspeci.md) gains a second-generation intake pipeline built around the documents teams actually hand over.

- **Document-type classification** — a Business Requirements Document, a Technical Specification and a raw epic each follow their own route through the agent
- **Technical Specification decomposition** — a TSD is broken into implementation areas and discrete requirements, so specifications that were previously unusable become a story backlog
- **Jira and qTest migration** — pull an existing backlog or test estate in, refine it, and push the result back
- **Multimodal pipeline** — diagrams and images inside a document contribute to refinement instead of being skipped
- **Unified integration experience** across every source
- **Requirements Traceability Matrix** generated alongside the refined stories

### New — Global Knowledge Base grounding

Every DeepSpeci pipeline can now be grounded in the Knowledge Base, not just the requirement text in front of it. Story generation is anchored in **exact Knowledge Base content** rather than approximate top-K matches, which materially improves terminology accuracy on domain-heavy requirements.

A **Knowledge Base lock** pins the selected sources for the duration of a run, so a long extraction can't drift when someone else updates a collection mid-flight. Long extractions are also **cancellable** now.

### New — Anomaly Detection Engine (Perf-Xi)

[Perf-Xi](../agents/perf-xi.md) gains a third mode alongside Workload Modeling and Script Automation. Upload performance test results, APM exports and infrastructure or database metrics, and the engine returns:

- **Anomaly detection** with validation of the ingested data
- **Correlation and root-cause analysis** with confidence scoring
- **Prioritised recommendations**
- A **performance health score**

It accepts JTL, APM, infrastructure and log inputs, and reasons across layers rather than reporting each metric in isolation.

### New — Perf-Xi Recording Studio

Script Automation gains a **Recording Studio** for capturing a live user journey directly, plus a redesigned input page. Captured journeys convert straight into performance script bundles for JMeter, k6, Gatling or Locust.

### New — Journey Identifier and Strategy Document

Two new assistants ship inside [QI PromptHub](../about/architecture.md):

- **Journey Identifier** crawls a running application and identifies the user journeys worth performance-testing — no manual journey inventory required
- **Strategy Document Generator** turns a source document into a structured test strategy, with parse, analyse, generate and export stages

### Improved — CaseGeni

A substantial round of test-design quality work:

- **Expected results for every test step**, not only per test case
- **Test case display** reorganised into distinct sections with step-specific expected results
- **Configurable story and acceptance-criteria limits**, so large requirements can be bounded deliberately
- **Accessibility (ADA) test cases** generated where the story warrants them
- **Scenario type** classification and corrected traceability back to source stories
- **Acceptance-criteria ordering** and coverage gaps addressed
- **Excel and CSV export** fixed — steps and expected results are separate columns, preconditions render correctly, text wraps, column widths are usable, and junk characters in Excel output are gone
- A cleaner, denser workspace UI

### Improved — Impact Analyzer

- **Prioritised ranking** of impacted tests, with impact classification reworked following pilot feedback
- **Impacted Tests** redesigned to match the New Tests layout
- Improved test-case relevance and scoring, and persistence across navigation

### Improved — DataGeni

- Accepts **CaseGeni CSV and Excel uploads** directly, with better schema inference
- **Foreign-key integrity** enforced across generated entities, so related tables stay consistent
- The generation stream stays alive through slow model responses
- Explicit `null` constraints are treated as missing rather than as a value

### Improved — Security posture

A VAPT assessment and follow-up review closed out the remaining external findings:

- **Safe download headers** enforced on proxied responses
- Hardened image handling through the backend-for-frontend route
- **TLS verification** enforced on outbound integration calls
- `INTERNAL_SERVICE_TOKEN` self-heals on existing deployments, closing a gap where an upgraded VM could be left without one
- DeepSpeci-specific hardening, plus pipeline state retention so a hardened session no longer loses in-flight work

### Improved — Accessibility Intelligence

Enabled for the BFSI sector by default, with a raised proxy timeout for deep crawls and correct forwarding of report downloads.

## Fixed

- **Knowledge Graph** — business-capability relations, acceptance criteria, business rules, impact paths, duplicate graph generation and test-case extraction all fixed; redundant writes reduced and Neo4j memory raised for larger graphs
- **Knowledge Base** — Word document uploads unblocked and upload errors surfaced clearly
- **Auto-PlayPilot** — framework generation and pipeline configuration corrected; sample repository configuration loads properly; test-execution fixes
- **Test Optimization** — reduction logic corrected
- **Projects** — traceability issues resolved
- **Journey Identifier** — waits for single-page-application login forms instead of checking visibility immediately
- **Perf-Xi** — Guidewire integration and workload concurrent-user consistency corrected

## Other changes

- Python runtime aligned on **3.14** across development machines, CI and deployment
- A **pull-request gate workflow** and branch-protection setup now guard the development branch
- Demo tenants can be seeded idempotently as isolated tenants with their own users
- `install.sh` works under Git Bash on Windows
- ZenRia gained Azure AI Search connector context for retrieval

## Known limitations

- **Test Code Conversion** appears in the Auto-PlayPilot mode picker but is not yet enabled; cross-language and cross-framework conversion is targeted for a future release.
- **Seven LLM providers** are listed in the provider catalogue, but server-side completion is currently implemented for **Google Gemini, OpenAI, Anthropic Claude and Azure AI Foundry**. Selecting Meta Llama, Mistral or Cohere stores the configuration but will not serve completions yet.
- **Twenty-one integrations** can hold credentials, but working data adapters exist for **Jira** and **qTest** only. Other providers connect and validate, then wait on their adapter.
- **Anomaly Detection Engine** supports file-based ingestion. Live observability integration is scaffolded on the agent but not yet wired to the UI.
