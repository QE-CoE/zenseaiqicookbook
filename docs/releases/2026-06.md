# June 2026

## Highlights

### New — Impact Analyzer agent

A new [Impact Analyzer](../agents/impact-analyzer.md) agent answers the question every change request raises: *what does this break, and what haven't we tested?*

Feed it a change request in plain English and it returns:

- **Impacted test cases**, ranked by a priority score with the linked requirement shown alongside each one
- **Coverage gaps** — areas the current suite leaves untested
- **Newly generated test cases** that close those gaps
- **Export options** for the impacted-test and new-test sets

Impact reasoning is grounded in the Knowledge Graph, so the agent traces from a change through business capabilities and user stories to the tests that actually exercise them.

### New — DocuProof (PDF validation)

[DocuProof](../agents/pdf-validator.md) compares two versions of a PDF and reports what materially changed — built for teams who sign off statements, invoices, policy documents and clinical reports.

- **Smart exclusion rules** mask expected churn (dates, prices, IDs, emails, phone numbers, percentages, page numbers) so genuine changes stand out
- **Custom regex rules** for domain-specific noise
- **Table structure analysis** — column and row-count drift, not just text
- **AI narration** explaining each difference in business terms

### New — Knowledge Graph rebuilt on Neo4j

The [Knowledge Graph](../agents/knowledge-graph.md) is now backed by a dedicated Neo4j graph database and models the delivery estate properly: business capabilities, modules, user stories, acceptance criteria, business rules, entities, test cases and defects, with the relationships between them.

This is what makes **impact paths** possible — trace a proposed change to the capabilities, stories, tests and defects it touches.

!!! note "New prerequisite"
    Neo4j runs as a Podman container (`zenseai-neo4j`, `bolt://localhost:7687`). `make install` provisions and starts it for you — see [Architecture](../about/architecture.md).

### New — Visual Xi full workflow

The Visual Detector agent ships its complete flow and is now surfaced as **Visual Xi** in the product. It compares a Figma design against a live URL and scores design compliance — see [Visual Xi](../agents/visual-detector.md).

- **Visual Eyes** — side-by-side, onion-skin and heatmap comparison
- **AI analysis** with CSS fix suggestions
- **Accessibility audit** and **link health** on the same run
- **Cloud device execution** via TestMu AI
- **Batch runs** — several Figma/URL pairs per execution
- **Excel import** for bulk page lists, plus a consolidated report

### New — Demo Builder Studio

A guided studio that stands up a realistic demo project — Knowledge-Base-powered Jira seeding and automatic story cleanup — so a working environment is ready for a walkthrough in minutes rather than hours.

### New — Jira and Confluence integrations

Jira moves from read-only ticket pull to a two-way integration: **import** requirements, **push** generated artefacts back, and manage credentials centrally. Confluence pages can now be ingested as Knowledge Base sources.

### New — Guidewire accelerator pack

End-to-end Guidewire support across the platform, for insurance teams working on PolicyCenter, BillingCenter and ClaimCenter:

- CaseGeni test generation tuned to Guidewire flows
- A Guidewire knowledge connector, including **Azure AI Search**
- Auto-PlayPilot domain packs
- Secure-Xi OpenAPI loader and Perf-Xi edge loader

### Improved — Knowledge Base

- **Payments-aware chunking** — payment flows are chunked so retrieval returns whole flows instead of fragments
- **LLM-assisted document ingestion** with clearer upload classification and coverage reporting
- **Embeddings normalised** to the storage dimension (3072), removing a class of silent retrieval failures
- **Connector-backed sources** — Jira, Confluence, GitHub and Guidewire alongside direct uploads

### Improved — Security hardening

A round of fixes from an external security assessment, covering P0, P1 and P2 findings:

- Source-integration tokens are **resolved server-side**; the browser no longer holds them
- **CSRF protection** and **SSRF guards** on outbound calls
- Legacy secrets **purged from `localStorage`**
- Security headers via Helmet with a tightened Content-Security-Policy
- Request **rate limiting**, with correct client identification behind a loopback proxy
- Access-token lifetime raised from 15 minutes to 3 hours to stop mid-run expiry

See [Security](../about/security.md) for the current posture.

### Improved — DataGeni

- A **source selector** so the agent can be launched standalone, not only from a pipeline
- **Connection Manager** for reusable database connections
- Per-card URLs, clearer navigation, and an agent icon in the source header

### Improved — QI PromptHub assistant

The PromptHub assistant became LLM-powered: describe what you want in plain English, and it matches a prompt from the library, collects the variables conversationally, and runs it against your configured model and Knowledge Base. Adds IDE advisory guidance and favourites.

### Improved — Auto-PlayPilot

- **Test Execution** is now a first-class step in the End-to-End QA Pipeline template
- Single-select test type and a uniform mobile configuration UI
- Browser dependencies are pre-installed at generation time, so runs no longer stall on downloads

## Fixed

- **Auto-PlayPilot** — breadcrumbs respect pipeline context; pipeline card file counts are correct
- **Knowledge Graph** — isolated nodes, duplicate nodes, test-case and defect relations, and business-capability redundancy all corrected
- **Payments Rail QE** — Knowledge Base context now reaches the agent via a direct call with the correct field name
- **Perf-Xi** — greenfield BRD path mode, TPS calculation and the MAU label corrected
- **Knowledge Base** — connector dropdown selection, upload classification and coverage cards fixed
- **DocuProof** — PDF buffers wrapped correctly for report construction
- **Visual Xi** — cloud-device runs now fail loudly instead of hanging when a session never starts; `SSL_VERIFY` is honoured by the Playwright subprocess

## Other changes

- `install.sh` generates a `DEFAULT_ADMIN_PASSWORD` and surfaces it in the install summary; Prisma failures are reported instead of masked
- Agent paths resolve relative to the repository root, so installs work outside `/opt/zenseai`
- Deployment gained self-healing per-service restart tracking and auto-discovers agents from `ecosystem.config.js`
- Frontend calls route through the Common Backend consistently, with silent token refresh
